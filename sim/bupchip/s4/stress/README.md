# Step 4 stress: corners and crossings

Stress benches for step 4 of `docs/BUPCHIP_CORE.md` (the Pocket wrapper around ARIA S1), written by an independent verifier to break the asset cache, the capture-to-receiver message path and the clock crossings. `../check.sh` runs every one of them as a job (work files in `$WORK/stress`); they can also run on their own. Everything is game-free; `run_reload.sh` needs the user's firmware (`src/fpga/mister/rtl/bupchip.hex`) and skips without it. Work files go to `sim/work/bupchip/s4stress` (`WORK` overrides), which git ignores.

```sh
sim/bupchip/s4/stress/run_all.sh        # everything below, one after another, about 25 minutes on one core
sim/bupchip/s4/stress/run_cstress.sh    # the asset cache, WAYS 1 and 2: 4 configurations x 6 latencies, psram.sv, 30 mutations (25 min)
sim/bupchip/s4/stress/run_capstress.sh  # the download path and its crossing (4 min)
sim/bupchip/s4/stress/run_slotswitch.sh # the Pocket's slot sequence through the real loader (30 s)
sim/bupchip/s4/stress/run_tick.sh       # the 48 kHz tick's crossing (iverilog, 2 min)
sim/bupchip/s4/stress/run_bounds.sh     # the asset window's bounds through tb_s4.sv (1 min)
sim/bupchip/s4/stress/run_pophead.sh    # the PCM FIFO's head race and the mute through tb_s4.sv (3 min)
sim/bupchip/s4/stress/run_xing.sh       # the command, frame, tick and pause crossings through the wrapper (2 min)
sim/bupchip/s4/stress/run_reload.sh     # reloads with different blocks through tb_s4.sv (firmware needed, 10 min)
```

Verilator is `/opt/verilator-5.040` if present (`VERILATOR` overrides); `run_tick.sh` uses iverilog, and `run_bounds.sh`, `run_pophead.sh` and `run_xing.sh` arm-none-eabi-gcc (their programs are the firmware, so they need no `bupchip.hex`).

## The asset cache (`tb_cstress.sv`)

Three phases (`+mode=pairs|holds|random|all`):

- **pairs**: the first load at every size (byte, halfword, word) and offset (0-15) of a cold line, then d = 0..44 other instructions, then the second load at every size and offset, on the same line (under fill), the next line (the prefetch's), a line at the same index with another tag, a line at the next line's index with another tag, or an unrelated cold line: 518,400 pairs. At psram.sv's fixed 5 clocks, d walks the second load across every position of the first fill and of the prefetch behind it.
- **holds**: with four lines valid, a hold of 1, 2, 3, 9 or 70 clocks dropped h = 0..60 clocks after a miss's W starts, or after a prefetch starts (610 items). During the hold the PSRAM's contents change (a reload), so after the release every line must miss and return the new contents.
- **random**: 300,000 loads mixed as `../tb_cache.sv` mixes them, with a hold and new contents every few thousand loads.

Checked on every clock: each completed load's bytes against the contents in effect; no completion on a read registered on the edge of a port-B write of the same data word or tag line (from the RAM ports, and through the poisoned data); every data M10K write goes into a line whose tag is invalid at that edge, and while held only in the first held clock; all 64 tags invalid at the first clock after a hold; each line's data equal to the PSRAM's when its tag is written valid, and every valid line every 2,048 clocks; no load waits more than 60 + 20 x the longest latency. It also measures each load's wait beyond the earliest clock the read-during-write rule allows ("excess").

**Two ways** (DARIA, `WAYS` = 2, built with `-DWAYS2`; `run_cstress.sh` runs everything for both). The phases are the same, on the 2-way geometry: "same index" is the same set, which with two ways keeps both lines, and the random phase's conflicts pick lines of a recent load's set. Every check covers both ways: a collision in either way's RAMs counts (the cache's rule takes both), a data write must go into a line invalid in the way written, all 256 tags must be invalid after a hold, and every valid line of both ways is compared with the PSRAM. Two checks are added: the line under fill is valid in neither way, and no set holds one line in both (`dup`, the fill's set every clock and all sets every 1,024 clocks). The excess wait is measured on the way that holds the line, against writes to the same word in either way. The replacement order (FIFO) changes no data, so its mutations are `../tb_cache.sv`'s (H1-H3).

With one way the cache is the step 4 file clock for clock (`../tb_cache.sv` runs it in lockstep), and a run here with `+poison_tdp=0`, `1` or `2` gives step 4's counts exactly (checked at latency 1-12 with pre-emption and prefetch). With the default `+poison_tdp=3` the counts can differ a little from step 4's: the poisoning tag model draws from the same random stream as the bench, and the order in which Verilator runs the two processes in a clock depends on the design's structure, so the stream is split differently.

## The download path (`tb_capstress.sv`)

300 random downloads per run: cartridges with 0-70,000-byte blocks (every size up to 49, sizes around 16-byte lines, odd lengths, R = 0, odd R, a header declaring more ROM than the file has), firmware files of 0-17,000 bytes (16,383-16,385 included); the loader at 2.5 `clk_sys` per byte, with random extra, or slower; downloads back to back (the next one starting in the clock after the last ends: a cartridge then a cartridge, a firmware download then either; a cartridge then a firmware download only with `+b2bfw` / `+xstream`, finding 1); with `+fwrise`, half the firmware downloads present their first byte in the clock `fw_download` rises (finding 4). After each download that is not followed straight away by another, both states are checked: `asset_size`, `asset_ready`, every block byte in the PSRAM model and the exact number of PSRAM writes; `fw_loaded`, the ROM words as port B takes them and the exact number of ROM writes. A reader stands in for the cache from two `clk_arm` clocks after `asset_ready` and `fw_loaded` until two after either falls, reading the block's last and first halfwords first and then at random, and checks each read against the block published by the END it ran after (reads in flight at a hold are dropped).

Messages too close together cannot happen any more (bup_capture queues every one, "Slot switches" below), and the bench counts them anyway from the toggle (`lost_x`, must be 0); `lost_s` counts a halfword or word completing while the one before still waits, which only `+fast` (a byte every 2 `clk_sys`) must cause. The checks wait 9-12 µs after a download, as END and FWEND now leave 64 `clk_sys` after its flag falls.

## Slot switches (`tb_slotswitch.sv`)

Written for the first hardware test's capture-error box (`docs/BUPCHIP_CORE.md`, step 5). That box turned out to be a synthesis artifact: Quartus had folded the sticky flags into constants. This bench checks the explanation first suspected, which test2's probe ruled out on the tester's Pocket (more than 286 µs between slots); the address-based capture stays as a safeguard. On the Pocket, `core_top`'s `is_downloading` stays high from the first requestwrite to allcomplete, and between slots only `download_slot` changes; the loader's 4-entry FIFO and 10-`clk_sdram` read machine can still hold the last bytes of the slot before. The bench sends the cartridge, BIOS, the two save slots, `highscor.rom`, `supercharger.bin`, `hsc.a78` and `bupchip.bin` as `data.json` orders them, with made-up contents, a bridge word every `+word` `clk_74a` (75), the next requestwrite (or allcomplete) `+gap` `clk_74a` after a slot's last bridge write and its first word `+pre` after that.

Taking bytes by slot flag, as before the fix (`+flags`), at a gap of 30 `clk_74a` or less: `hsc.a78`'s last byte reaches the firmware download, which sees a word begin midway (`seq_err`, the box); at 20 or less the firmware also loses its own last word to allcomplete, and the cartridge its block's last bytes to the BIOS slot. Taking them by address with the windows (`bup_capture.sv`, "Which bytes are the BupChip's"), every gap from 400 down to 0 loads both exactly, and the probe counts what the windows sorted out (bytes of another slot under a flag, bytes taken after a flag fell, none dropped). `run_slotswitch.sh` runs gaps 400 to 0, with and without the block, the firmware first, no optional slots, the next slot's first word 20 `clk_74a` behind its request, words every 60 `clk_74a` and 5-stage synchronisers, then the two `+flags` runs that must raise `seq_err`.

## The PCM FIFO's head and the mute (`run_pophead.sh`)

CoreTone keeps the FIFO above its watermark at speed, so no `../check.sh` song pushes into an empty FIFO, which is where `bupchip_peripheral` raises `pcm_available` a clock before its M10K presents the frame and the wrapper's `tick_hold` matters. `fw_pophead.S` does exactly that, 6,000 times at every tick phase. `../tb_s4.sv`'s `+forcetick` forces a tick onto that clock once (from 5 ms on), a sure collision; its rdw check flags any tick that takes the head from a collided read. With `FAULTAT`, the firmware writes FAULT after frame M = 3,051 and goes on pushing: the frames up to M - 1 (or M) come out, and every later one must be 0.

## The wrapper's other crossings (`tb_xing.sv`)

`run_pophead.sh`, `run_bounds.sh` and `../tb_s4.sv` run the wrapper with `clk_arm` edge-aligned to `clk_sys` only, and send one command per song. `tb_xing.sv` puts the whole wrapper (on `../psram_standin.sv`) under the clocks the toggles are meant to survive: `clk_arm` at 2 x or 1.5 x `clk_sys` (NTSC and PAL) or asynchronous at 16-29 MHz with jitter, and `clk_74a` off by up to +-200 ppm with jitter. The firmware, `fw_xing.S`, loaded through the firmware slot, enables PCM with watermark 0 and pushes one frame per command it pops: `{command byte, the asset byte at offset (k - 1) x 37 mod 4,096, k}`, the asset byte read through the cache (misses, prefetches, late hits, and prefetches past the 4,096-byte block's end). The bench sends N commands in bursts of 1-7 at 2-4 `clk_sys` apart (the toggle crossing's limit is about 2 at the synchronous ratios), with noise on `cmd_data` outside each command's clock (as `top.sv`'s `bup_cmd_data_eff` may carry under `BUPCHIP_FORCE_CMD`), about 1.1 ticks per command so the PCM FIFO is mostly empty and the pushes land at every phase of the pop; `+pause` adds random pause windows.

Checked: every nonzero frame captured on `clk_sys` (at the wrapper's `frame_cap`) is the next command in order, with the right asset byte, each once, and all N come back; no pop while paused and no nonzero frame captured with pause high for the last 12 `clk_sys`; the number of ticks between the first and last against the elapsed time at the `clk_74a` rate as built (+-2); the CPU never halts; no command or PCM overflow and no capture error in `dbg_status`. Wrappers that must fail: `cmd_nohold` (the command byte taken from `cmd_data` at the `clk_arm` detect instead of the held register), `tick_nohold` (without `tick_hold`; one command per tick, 2N commands) and `pause_nogate` (pops not gated by pause).

## Findings

All four are fixed in the step 4 RTL, and the benches that found them now run in `../check.sh`.

1. **A firmware download starting right after a cartridge download corrupted the message stream** (`bup_capture.sv`). The cartridge's tail WRITE and END wait in flags for the 5-clock spacing, but FWWRITE was sent directly when a word completed. If the firmware download's first word completed within about 13 `clk_sys` of the cartridge's `load_end`, an FWWRITE left 1-4 `clk_sys` after the END: `lost` rose, and at 1-2 `clk_sys` the receiver copied the FWWRITE's payload for both toggles, so the END was lost (`asset_ready` stayed 0, the BupChip silent until the next cartridge) and one FWWRITE was written twice. On the Pocket the firmware slot (0x109) would load after the cartridge slot at core start with `is_downloading` high across both (`core_top.v:631-637`), so only the bridge's slot handshake kept them apart. **Fixed:** FWWRITE now waits like the tails, in a one-word register (`fwword_pl`), second in priority after FWSTART; words come at least 10 `clk_sys` apart, so it never waits more than 9.
2. **The 64-clock tag sweep was not covered by `../check.sh`.** `../tb_cache.sv` and every reload in `../check.sh` put the same contents back, so stale tags still held the right bytes: with the sweep removed from `bup_asset_cache.sv`, `../tb_cache.sv` passed. Through the whole wrapper it does not show either: with the sweep removed, `run_reload.sh`'s A then N (every sample byte different) still gives N's PCM exactly, because none of the 63 lines still valid at the release is read before its index is refilled. **Fixed:** `tb_cstress.sv`'s holds change the PSRAM behind every valid line and catch `sweep_none` and `sweep_short`, and `run_cstress.sh` is a `../check.sh` job; `../tb_cache.sv` has a directed scenario G that does the same, and `../run_cache.sh` mutates the sweep away and one tag short.
3. **The PCM FIFO's head race was not exercised by `../check.sh`.** `+forcetick` forced its tick where `pcm_available` first rises, which is where the firmware enables PCM over the boot's prefill; that head was written long before, so there is no collision there, and no `../check.sh` run underflows. A wrapper with `tick_hold` removed passed `+forcetick` with identical PCM on both streams. **Fixed:** `run_pophead.sh` is a `../check.sh` job, and `+forcetick` now fires only on the clock after a push into an empty FIFO with PCM already enabled.
4. **A firmware byte in the clock `fw_download` rises was dropped** (`bup_capture.sv`, found in review, then by `+fwrise`): the rise branch skipped the byte, so byte 0 was lost and `seq_err` raised. **Fixed:** that byte starts the new download's first word.
