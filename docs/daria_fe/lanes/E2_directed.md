Lane E2 is point 4 of the original lane-E task: the directed tests of design 12.1 (`D/fe_dir/`) and bench.md 7.9 item 7. The tests build synthetic DPC+ and CDF-family images from scratch and run them through tb_daria with `FE=1` in mode A, so upstream's ARM runs the calls.

**Status.**

- **Built and run.** There are 48 directed tests, covering every row of the 12.1 table except `bios`, which the bench cannot do (section 5).
- **Stage-0 reference: all 48 pass.** Every bad count is 0 and every test reaches every coverage bin it needs. This holds in both stage-0 builds:
  - the stage-0 bench as committed (`d729ba7`);
  - the live bench built with `FE_STAGE0=1`.
- **Real `daria_fe` (E1's stage-1 bench, `fe_shadow.svh` md5 `acd6550553fa…`): 47 of 48 pass.** The same holds with the poisoned RAM model, and with `+fe_merge_hook=1` 30 of the 31 CDF tests pass. The one failure is `cdf_jump_ffe`:
  - **It is a real behavioural difference in `daria_fe`:** `obus_exposed` on a fast jump whose opcode is at $1FFE (section 6.1).
- **Two bench gaps found and already fixed.** On an earlier stage-1 bench (md5 `85ffaaf68c07…`), two more tests failed. Both were gaps in the stage-1 bench, not RTL errors: R3 on a queued RMW service pair, and A1 after `rmw_seed` (sections 6.2, 6.3). E1's current bench fixes both:
  - R3 now runs once both sides are quiet;
  - a new class, `rmw_merge`, covers the merge after `rmw_seed`.

  With that bench both tests pass.
- **Mutation check:** 9 hand-made mutants of the `daria_fe` RTL. Each is caught by the directed test meant to see it (section 4).

## 1. What is built

### 1.1 The call routine

The routine is a small script interpreter: about 90 Thumb halfwords plus a 26-word ARM helper. It is entered in Thumb state at the scheme's entry with upstream's call state:

- r0-r12 = 0;
- SP = the scheme's stack;
- LR = $F0000000;
- SYS mode;
- counters in FIQ r8-r10 and frequencies in FIQ r11-r13.

Each call does this:

1. Bumps a call counter in cart RAM (DPC+ $40000800, CDF $400003F0).
2. Runs script[min(count, n-1)] from a table in ROM.
3. Returns with `BX LR`.

Script operations:

| Op | Action |
|---|---|
| `W8` / `W16` / `W32` | write cart RAM |
| `ADD32` | add to a cart RAM word |
| `COPY` | ROM to RAM, word by word |
| `FILL` | fill RAM with a word |
| `FSET` / `FADD` | set or add an FIQ register: switch to ARM state, `MSR CPSR_c,#$D1`, `MOVEQ`/`ADDEQ` r8..r13, `MSR CPSR_c,#$1F`, back to Thumb |

So the four kinds of call the task names are all scripts of this one routine:

- "return": an empty script;
- "change frequencies": `FSET`/`FADD` 11..13;
- "rewrite a waveform pointer": `W32` at the scheme's waveform base ($1B0, CDF0 $7F0);
- "write cart RAM": `W8`, `COPY`, `FILL` (including the CDF stream tables, which upstream snoops).

### 1.2 What the images hold

- **6507 code: the kernel.** Clear RIOT RAM, the test's init, then a frame loop: VSYNC, the body, a few `WSYNC` lines, `M_FRAME++`.
  - It uses no immediate below $E0. In CDF fast mode an `LDA #` in the stream range is a fetch, and so is `LDX #`/`LDY #` on CDFJ+ with the options. In DPC+ fast fetch an `LDA #` below $28 is a register.
  - DPC+ code starts at $1100, above the register file.
- **6507 code: the markers.** RIOT RAM $FF counts completed test bodies (`dir_marker`). $FE counts the program's own self-checks that failed (`dir_selfcheck_err`). $F0-$F2 hold the failing check's address and value; `dircheck.py` names the check from the `.meta`.
- **DPC+.**
  - Driver area: "DPC+" twice. For revision 1, the CRC32 of the first 3 KB is forged to $A08CFB13 by solving for 4 bytes over GF(2).
  - Entry $0C08.
  - Display data at $6C00 and a NOTE frequency table at $7C00, both synthetic patterns.
- **CDF family.**
  - Signature words: CDF0/CDF1/CDFJ ×3, or `PLUS` `CDFJ` 1.
  - The option words when asked: LDX $135200A2, LDY $135200A0, offset $E24220xx, audio-size scan.
  - The stream tables and waveform pointers at each revision's bases, in the driver area that the RAM init copies.
  - Entry $0808; for CDFJ+, the entry and stack words at $17F4/$17F8.
  - The `COPY` sources sit in ROM no bank uses: $0C00-$0FFF for CDF0/1/J, $7800-$7FFF for CDFJ+.
  - 64 KB images (`digital_*`) fill $8000-$FFFF with a sample pattern.
- **`mkimg.py` checks the classification itself** (a Python model of detect2600). `dircheck.py` checks that run.log's `detect2600:` line agrees.

## 2. How a test is judged

### 2.1 The two builds

- **Stage 0 (`FLAVOR=s0`).** The stage-0 bench exactly as committed at `d729ba7`: `tb_daria.sv`, `fe_shadow.svh` and `daria_shadow.svh` from git, plus the monitor.
  - The reference front end is upstream's own code, so every bad count must be 0. The FE lines checked are `FE shadow:` (dout, state) and `FE detail:` (port, rom, ram, pointer, jump map, L3).
  - This build is independent of the bench being edited now.
- **Stage 1 (`FLAVOR=s1`).** E1's bench in the tree: `daria_fe` on `fe_mem`, mode A, all of design 12.4's checks.
  - The verdict is the bench's own `FE result:` line.
  - Every counter of `FE bad:` must be 0. Its counted classes (`FE classes:`) are reported per test.

### 2.2 Coverage

`fe_dir_mon.sv` counts named bins at upstream's commit edges and at its audio, call and DMA events. The 6507's bus is sampled pre-edge, as the bench does.

| Area | Bins |
|---|---|
| DPC+ register reads and writes | per function/index or group/index |
| DPC+ fast fetch | substitutions, on opcodes, armed by data bytes |
| DPC+ wraps and window flags | wraps of PUSH, WRITE, DATA, FRACDATA; window flags FF/00; FRACLOW per revision; PARAMETER per pointer value |
| DPC+ CALLFUNCTION and service | CALLFUNCTION values; service fill/copy, each clamp, count 0, latched during a DMA, RMW; audio grants inside the service range |
| DPC+ NOTE | NOTE commits; ticks at C+k; NOTE during a refresh; capture offset |
| CDF fetches and jumps | fetches per stream, amplitude, by arming byte, through the offset, out of range; jump arming (at bank-end addresses, by data reads), jump substitutions per remaining count/stream and at $FFE/$FFF, cancels, $4C with no map, the $7FFE exclusion |
| CDF registers | DSWRITE (into the CDFJ+ tables, wrapped, below $800), DSPTR, SETMODE, CALLFN (RMW, while busy) |
| Hotspots | reads and writes, bank changes, substituted operands at hotspots |
| Digital audio | the route: ROM <32 K, ROM ≥32 K, RAM window, none; pointer and size captures |
| Calls and merges | merges that set or keep counters; ticks at M+k |
| Phases | E0 to latch and latch to E0 spacings; short commits; RSYNC |
| Resets and pauses | console resets inside a call, a service or init; injections |

Each test lists the bins it needs and a minimum for each. A test whose feature never fires fails.

### 2.3 Injections

These are in the monitor. Neither `fe_shadow.svh` nor `tb_daria` is touched.

- **`+dir_rst=1|2|3|4`.** Drives `tb_daria.reset_in` for `+dir_rst_len` clk_sys, starting `+dir_rst_dly` after one of:
  - the n-th call accept (1);
  - the n-th DPC+ service start (2);
  - the end of the load, during init and F6 (3);
  - the n-th release of the console reset (4).

  The frame-based `+hard_reset_at` of stage 0 cannot land inside a call: VSYNC is a 6507 write, and the 6507 is held during a call.
- **`+dir_pause=1|2|3`.** Forces `dut.pause` for `+dir_pause_len` clk_sys, starting `+dir_pause_dly` after one of:
  - the n-th E0 (dly 1-5 is phase 1, 6-11 phase 2) (1);
  - a call accept (2);
  - a service start (3).

  `+dir_pause_rep` repeats it. In this Verilator, `release` does not hand an input port back to its constant driver, so the pause ends with a force to 0.

### 2.4 Verdict (`dircheck.py`)

A test passes only if all of these hold:

- the run finished without a simulator error;
- detect2600 reported the expected scheme and revision;
- the FE shadow ran;
- every bad count, must-be-0 counter and `FE result` is clean;
- every required bin is met;
- the 6507's self-checks are 0.

## 5. What the bench cannot do

- **`bios` (`use_bios`, class `pre_lock`).** `tb_daria` ties `bypass_bios` to 1 and `bios_out` to 0. There is no BIOS image, so the BIOS path cannot run in this bench. Forcing the port would boot a 7800 BIOS of zeros. Not attempted.
- **`short_phase1` from RSYNC.** `rsync_*` writes RSYNC at every cycle position of a line, and every E0→latch spacing stays 6.
  - `fe_shadow`'s reload log shows no re-phasing reload other than the post-reset handoff.
  - The reason: in `TIA.sv` the RSYNC write restarts `hclk_counter` at the write itself (`.reset(rsync)`). The write is always at the same point of the CPU divider, so the `hclk.edge_p2 && rsynd` reload that follows always finds `pclk_div == 1`, which is a no-op (bus.md B2's "d=1").
  - So a CPU-written RSYNC cannot misalign the divider here. The 2- and 10-clock phases of design 12.1 / bus.md B2 are unreachable in mode A.
  - `short_phase1` is covered only by the unit benches (`tb_fe_seq`, `tb_fe_core` with `fe_phase_gen`).
- **Pause.** `dut.pause` is tied to 1'b0, so it is forced, and released by forcing 0 (section 2.3). This is a bench stand-in for `pause_core`, not the wrapper's pause path.
- **`hard_reset` "during F6".** With the sticky hold (bench.md 7.4.2), the console reset is held high through init and F6, so a pulse inside them makes no edge (`hard_reset_init_cdfjp` checks that nothing breaks). The nearest real case is `hard_reset_rel_*`: a new reset edge 3 clk_sys after the first release, so a second init and F6 follow the first at once.
- **`live_override`.** The scheme comes from detect2600 at load, so it cannot be changed live in tb_daria.

## 6. Issues found

### 6.1 Issue 1 (RTL/design): `obus_exposed` on a fast jump at $1FFE (`cdf_jump_ffe`)

**What the test does.** A CDF fast JMP has its opcode at $1FFE, with $00 at $1FFF and $00 at the next bank's first byte, so the map bit is set from the linear image.

1. The low operand at $1FFF is substituted by stream 33's byte ($C5).
2. The high operand is read from $0000 (the 13-bit address wraps), i.e. TIA CXM0P. Only D7-D6 are driven there; D5-D0 come from the open bus.

**Upstream.** After the commit, `expected_address` wraps to $0000, so the substitution ends. `d_out` falls back to ROM[$1FFF] = $00 for E0+7..E0+11, and the open bus holds $00. The jump goes to $00C5, a zero-page routine.

**`daria_fe`.** `fe_do` holds the committed $C5 (design 2.4: "fe_do holds the latched byte from C until the next E0+2"). The bench's O1 sees the TIA read return $05 with `daria_fe`'s bus: "read_DB 00, with daria_fe's bus 05". On hardware the 6507 would jump to $05C5.

**Result.** `obus_exposed` = 5, one per frame, which design 9.6 lists as must-be-0.

**How general it is.** It needs a substituted cartridge read at $1FFF followed by the wrap to $0000. Other paths where the last cartridge read of a cycle is followed directly by a TIA or RIOT read with a partial `oe` were not found:

- every other substituted read is followed by a cartridge opcode fetch, which fully drives the bus;
- code running from RIOT RAM fetches from RIOT RAM, which also drives fully.

A DPC+ analogue, a fast-fetch `LDA #` with its operand at $1FFF, would expose the same way. It was not run, because upstream's TIA-sourced opcode makes the 6507 execute TIA space.

**Fix options, for the lead.**

- (a) Accept it and document that a fast jump or a substituted operand at $xFFF differs on hardware.
- (b) In `daria_fe_core`, after a substituted read at `a_in[11:0] == $FFF`, load `fe_do` with the mirror's ROM byte at C+1, as upstream's `d_out` does. This costs a term in `fe_do`'s load and the existing `k1b` lane.

### 6.2 Issue 2 (stage-1 bench, lane E1; fixed in E1's current bench): R3 on a queued RMW service pair (`dpc_svc`)

**What the test does.** `INC $105A` over ROM $01 latches a copy, then a fill latched while the copy runs (`rmw_svc`), into the same 16 bytes at $600.

**What the earlier bench reported.** R3 reported `svc_ram_bad` once per pair ("13 of the 16 bytes at $1200 differ"). R3 paired the n-th upstream DMA-busy fall with the n-th `u_copy.run` fall and compared service n's range. `daria_fe`'s engine finishes both services before upstream's slower DMA (it re-reads DDR) finishes the first, so service 1's range was compared while one side already held the fill.

**`daria_fe` is right.**

- The monitor counts 216 `run` rises for 216 services, so the engine does not merge the pair.
- The 6507 then reads all 17 bytes back through DF6DATA, and L1 compares `daria_fe`'s fetcher output with upstream's at every read: 0 differ.
- Every other service result read back is also equal, including the source and destination clamps and the 255-byte fills over the audio.

**Fixed.** E1's current bench runs R3 "once both sides are quiet", and `dpc_svc` passes.

### 6.3 Issue 3 (stage-1 bench, lane E1; design-accepted value; fixed in E1's current bench): A1 after `rmw_seed` (`rmw_call_cdf`, no hook)

**What happens.** In 2 of the 1,536 RMW pairs a tick lands exactly on upstream's merge edge M of call 1. Call 2's seeds then differ by one tick: `rmw_call` in design 9.5; lane C's C-3; the bench counts `rmw_seed` 2.

**The consequence the earlier bench did not class.** In mode A, call 2's returns come from upstream's ARM, so a voice the ARM leaves unchanged returns upstream's seed. Upstream keeps its counter (return == seed). `daria_fe` compares that return with its own seed, which differs by a tick, and loads it. The counter is then off by the ticks since M until the resync: `counter[1] b0a5e6af, upstream b21b29ca`.

The earlier bench counted this as `audio_bad` (2).

**Why this is mode-A only.** In mode B and on hardware, DARIA's own ARM receives `daria_fe`'s seeds and returns them, so the comparison is consistent there.

**Fixed.** E1's current bench classifies the merge after an `rmw_seed` as `rmw_merge` (2) and resyncs, and the test passes. With `+fe_merge_hook=1` neither class occurs.

### 6.4 Observations (no action)

- **`release` in Verilator 5.040.** It does not restore a force on a module input port tied to a constant: the port stays forced. The monitor ends a pause with a force to 0.
- **Shared infrastructure.** `run_daria.sh` rewrites `$WORK/patched/*.sv` on every call, so its `find -newer` check rebuilds every time. An incremental rebuild in an object directory whose `.gch` files it deleted then fails: "Vtb_daria__pch.h.fast: No such file". `run_dir.sh` works around both with its own stamp and clean builds. One clean build hit a transient `g++` bus error under load (load average 6.6) and passed when retried.
- **Lane A O-1, lane D issues 1 and 3.**
  - No `a_p32_late` or `p32_reset` occurred in the reset tests.
  - `clk_arm` is never jittered.
  - `fe_phase_gen` is not used.

### V.4 Fixes in this lane (all re-run: `s0` 50/50, `s1` 49/50)

1. **Variant tests could not fail their own counts (F14).**
   - `digital_cdfj_s5`, `_s200` and `digital_cdf1_s100` passed with their `+fe_slat`/`+lat` dropped.
   - `fe_dir_mon.sv` now records `tb_lat` (tb_daria's `lat`) and, in stage-1 builds, `fe_slat`.
   - `tests.py` requires `tb_lat == lat` and `s1:fe_slat == slat`. A new `s1:` prefix marks a bin that `dircheck.py` checks only in stage-1 logs.
2. **Vacuous passes in `dircheck.py`.** A log passed in each of these cases:
   - "FE shadow" showing 0 latches and 0 commits;
   - "FE detail" or "FE counts" with 0 read latches compared;
   - a stage-1 log missing its "FE result" line.

   Each of these is now a failure. Four doctored copies of a passing log, one per case plus a `dirchk_*_bad` bin, each FAIL with the right reason.
3. **The self-check counter wrapped.** `M_ERR` (RIOT $FE) wrapped at 256, so 256 failed checks read back as 0. The hotspot tests run about 300 checks. `ckfail` in `mkimg.py` now saturates it at 255. Every image changes, but no test's flow does.
4. **The build stamp ignored the mutants.** `run_dir.sh`'s stamp did not cover the `FE_DIR_MUT` copies, so a flavour rebuilt with other mutants would have reused a stale binary. The stamp now includes the copies' contents and the mapping.
5. **The ≥ 32 KB ROM sample route was never compared.**
   - The bench masks every remote sample (`dig_rom_lag`, 97 per digital run) and then deposits upstream's audio state. So the path sample port → `rdat` → nibble → amplitude was not compared at all (M31).
   - `fe_dir_mon.sv` (stage 1) now pairs, in order, every amplitude written from a ROM sample:
     - upstream's: `AUDIO_ROM_WAIT` & `rom_done`;
     - `daria_fe`'s: `am_rom`.

     For each pair it compares the value and the sample address.
   - A refresh that either side dispatched in the bench's merge window (M, M_fe+1] is counted as `dirchk_rom_merge` and not compared. This is the bench's `merge_amp` class: `daria_fe` merges the counters 6 clocks after upstream.
   - Real RTL in every digital test: 74 local and 91 remote pairs, 0 bad. `digital_cdf1_s100` has 1 merge pair, the same refresh the bench counts as `merge_amp`. In that pair `daria_fe` read $0C1A, upstream $0C00: the refresh used the pre-merge counter.
   - `dircheck.py` fails any `dirchk_*_bad` above 0. The digital tests require `s1:dirchk_rom_lo_n`/`_hi_n` ≥ 30.
6. **The handed-over rule was not exercised.** The rule is lane A O-1 / lane D issue 1: `a_p32_late` under a console reset.
   - No reset test reset the console inside a DSWRITE cycle. `p32_reset` was 0 in every reset test.
   - New: `+dir_rst=5`, a reset at the n-th CDF DSWRITE/DSPTR cycle, seen at E0+1. With `+dir_rst_rep`/`+dir_rst_max` it repeats, the delay stepping +0..3.
   - New tests `hard_reset_dsw_cdfj` and `hard_reset_dsw_cdfjp`. Each has 5 resets, 4 of which rise inside the DSWRITE cycle's phase 1 (`reset_in_dsw_ph1`).
   - Stage 1: `p32_reset` 2 in each test, `a_p32_late` 0, all checks clean. The bench's classification works, and nothing else fires there.

`summary.py` now reads `s1:` bins.
