## 2. How the bench is put together

### 2.1 Side U: upstream (`fe_rand_up.sv`)

Instantiated as `cart2600` instantiates them (src/fpga/mister/rtl, read only):

- `mapper_dpcplus` and `mapper_cdf` (reset `reset || mapper != X`, `access = phi2 && arm_driver_run`), the selected mapper's `d_out`/`oe` mux (cart2600.sv:211-233), tb_daria's one-clock ROM (`rom_do <= rom[rom_a]`);
- `arm_mapper_tables` (family 2 for CDF, sys writes from init and `pointer_update`, clk_arm writes from the ARM port), `arm_mapper_ram_init` (on `load_end_d`), `arm_mapper_writeback` (priority on the ARM port), `cdf_fastjump_table` (the load stream), `arm_mapper_audio` (family = `init_family`);
- `cart_ram_tdp` itself, with top.sv's port A (`mapper_en = init_busy ? wr|rd : !pause`, $FF bytes on pause), cart2600's address mux, `cartram_wr`/`cartram_rd`, `access_taken`, `address_change`; the 2600 path only (top.sv:752-757: without `tia_en` no 6507-side write reaches the RAM).

Three models complete it, because `arm_mapper_controller` imports `arm7tdmi_pkg` and `arm_mapper_memory` needs the DDR3 channel:

- **the controller**, both halves, copied statement for statement (`arm_mapper_controller.sv:86-361`) without the package; the CPU behind it is the agent (2.4);
- **the memory's DMA and sample ports**: both clk_sys halves exactly (toggles, payloads, busy, done, `dma_ready = shadow_ready_sync2 && !dma_busy`), both clk_arm state machines exactly (DMA_IDLE/COPY_COMMAND/COPY_WAIT/RAM_WRITE one byte per accepted edge; SAMPLE_IDLE/CHECK with the one-word cache/COMMAND/WAIT); the DDR3 channel as one server with a random latency per access (`+ddr_lat_min`, `+ddr_lat_max`, `+ddr_long` per mille up to `+ddr_long_max`), the DMA served before a sample; the load path as `shadow_ready` (cleared at `load_start`, set two clocks after `load_end`);
- **the subsystem's** `mapper_reset_arm` (two clk_arm flops of the console reset).

### 2.2 Side B

- **Default:** `daria_fe` + `daria_mem #(.WIN_KB(32))`, mode A as design 12.4 wires it: `clk_arm` = the bench's 5 × `clk_sys` at fixed phase (lane D issue 3: no jitter; the guard never locks, `det_lock_a` stays 0); `cart_reset` = the bench's `effective_reset`; `d_in` = the CPU's write byte; `cart_win` emulated (the download, then 64 clocks); `cpu_ready` = upstream's `arm_online_sync2 && shadow_ready_sync2 && !effective_reset`; the cart RAM mirror of the ARM's writes into port A on the clk_arm edge `cart_ram_tdp` takes them (writeback and DMA excluded); the front-end ROM from the load stream through `cap_we`; the sample port answered with the image byte after `+slat_min..+slat_max` clocks; the hook (`hk_en`, upstream's `call_done` and returns) at random per epoch (`+hook=2`).
- **`-DSELF`:** a second `fe_rand_up`, fed the same inputs and the same CPU agent. By default `+strict=1`: no class may mask anything, so any difference is a failure. `+self_ofs=N` gives side B's DDR model another random stream (different DMA and sample latencies); the classes then apply as for `daria_fe`.

### 2.3 The bus and the console

- **Clocks:** `clk_sys` 70 ns, `clk_arm` 14 ns, every `clk_sys` rising edge also a `clk_arm` one (mode A's shared edge).
- **Phases and stalls:** `fe_phase_gen` (`EXT_BUS`), all presets via `+pg_mode` (phase 1 of 2/4/6/stretched, phase 2 of 6/10/stretched and of 4 while the driver is off, pauses in either phase, its own random busy). Its stall input is top.sv's `arm_call_stall` with the hold of bench.md 7.4.2: `tia_en && (up.call_busy || (!up.init_busy && (up.dma_busy || B.arm_dma_busy)))`, so "a DMA model holds the 6507 while either side's service runs". Held cycles re-present the read with its `pclk0` hidden after the first (`stall_cycle_taken`).
- **The stream** (tb_fe_core's, extended): 52% the next program byte, TIA/RIOT accesses, the scheme's registers with meaningful values (FASTFETCH, PARAMETER, CALLFUNCTION 0/1/2/FE/FF, field writes, PUSH/WRITE, NOTE, WAVEFORM; DSWRITE, DSPTR, SETMODE with digital mode, CALLFN), hotspots (reads and writes), jumps (anywhere, to $xFF0-$xFFF, onto the arming opcodes planted before the hotspots), repeated addresses. It obeys the 6502's write sequencing: after a store comes an opcode fetch; a write that does not continue a run needs three reads since the last write (a store is the last cycle of an instruction whose opcode and address the CPU fetched first); the opcode fetch after a store skips a byte (it is never the operand an arming opcode before the store expects) and never lands in `$1000-$107F`; a read the mapper took as an arming opcode (`$A9`, `$A2`/`$A0` with LDX/LDY, `$4C` for a fast jump) is followed by its operand, a cartridge read at PC, as fast-fetch code always does (if an RMW's own read armed it, the opcode fetch after its writes reads the stack page); the only write runs are an RMW's two writes to one address (the old value, then the new: `INC $105A` over 01 gives a copy then a fill, `INC $1FF3` over FE two calls) and push runs to the stack; so a hidden write is never a cartridge's, and the cycle a one-clock stall dip lets through (the held fetch's successor) is never a write. The CPU in reset only reads, and only the stack page (A12 = 0), so the cycle in which a console reset ends is never a cartridge access (a 6502 leaves reset through PC, stack and vector reads). `+rst_bus=1` reads anywhere in reset and adds the release planner (2.5). The access of a cycle is chosen at the E0 before it (the stream is one cycle ahead of the bus: `gen_next` runs at the `load` edge, where the generator presents the value it computed at the previous one).
- **Epochs** (`+epoch`, default 50,000 cycles; every campaign group sets 25,000, the `+rst_bus=1` groups 10,000): the download raises the console reset; during it the bench picks the scheme (`+only`; "all" rotates DPC+ sf 0/1 and CDF0/1/J/J+ with and without the fetch offset), revision, LDX/LDY, offset, `cdfj_entry`/`cdfj_stack`, `audio_size_addr` (none, in RAM, or 2% above $7FF8: `size_over32k`), `rom_size` (32 KB, or up to 64 KB: samples beyond the front-end ROM go to the sample port), the hook; builds the image (tb_fe_core's patterns: $A9/$A2/$A0 + in-range/out-of-range/$27/$28 operands, `$4C o1 o2`, $4C at every layout's bank ends, arming opcodes before the hotspots; waveform pointer words for every digital route; size words) and streams it a byte per clock with gaps. The console stays in reset until both inits are done (the sticky hold of bench.md 7.4.2). One event per epoch, in turn (`(epoch + seed) % 4`): a console reset at any moment (a call, a service, mid-cycle), a 7800-mode interval (the 2600 driver off; only with nothing in flight), a non-ARM scheme interval (CDF epochs only: a DPC+ epoch whose turn it is gets no event), none. The counters `ev_reset`, `ev_7800`, `ev_nonarm` and `ev_none` count what happened. `+resets=N` adds N more console resets per epoch, spread over the rest of it (the `+rst_bus=1` groups use 6).

### 2.4 The ARM agent

The CPU behind both controllers (clk_arm): it halts 0-4 edges after `halt_req`, presents `state_ready` 75% of edges, runs each call for 0-40 (15%), 40-640 (70%) or 600-4,100 edges, and returns through `return_fetch`. While it runs, and only while the 6507 is held with every `pclk0` hidden since the taken one and 4 clocks quiet, it writes 0-6 cart RAM words (30% none): pointer, increment, waveform-pointer and size words, the DPC+ NOTE table and waveform/display data, random words; random byte strobes (20% partial). Each write is held until `cart_ram_tdp` accepts it, which is never on the shared edge; side B gets it on the same edge. The returns: each counter kept (40%; each side gets its own seed back, as its own ARM would), new (50%) or seed + 1 (10%); each frequency kept (30%) or new.

For `daria_fe`: `ret_tog` per call number. If `u_fe` flipped `call_tog` for the call before upstream's first capture edge, the six return words are written into state RAM F8-FD on upstream's six capture edges and `ret_tog` flips with `complete_toggle` (`ret_sync`); otherwise on the six clk_arm edges after both have happened (`ret_late`, design 9.5).

### 2.5 The release planner (`+rst_bus=1`)

Design 9.5's `rst_release` needs a console reset released inside a 6507 cycle that commits an action waiting for a ready flag. A 6502 in reset only reads, and with `+rst_bus=1` alone the release cycle is a read chosen while the reset is high, so only DPC+ DFx reads were reachable (F1_fixes.md, "What lane E3's random bench needs"). The planner makes all five kinds reachable. It is a bench option: no 6507 program does this.

- **When.** At a `load` edge in a reset's tail (`reset_r` low, `rhold` high), in 2600 mode, with probability `+rst_rel` (per mille, default 700), it takes the next cycle as the release cycle.
- **What.** DPC+: a DFxDATA/DFxDATAW/FRACDATA read ($1008-$101F, 30%), PUSH ($1060-$1067, 15%), WRITE ($1078-$107F, 15%), CALLFUNCTION 1 or 2 alone (20%), or as an RMW's first write (20%: the next cycle writes the value + 1 to $105A, so 1 then 2, or 2 then 3). CDF: DSWRITE ($1FF0) or DSPTR ($1FF1), 50% each. The stream's own write rules (2.3) do not apply to these two cycles; the opcode fetch after the store follows them.
- **The release edge.** `rel_hold` holds the console reset past its tail; `rel_own` takes the tail itself out of `eff_reset` until it has ended. In the planned cycle the reset is dropped at the edge where phase 1 has `rel_m` clocks left (`pg.cnt <= rel_m`, `rel_m` 1 (30%), 2 (30%), 3 (25%) or 4 (15%)), so `rst_fe` is high up to the edge C − `rel_m` and low at C (with no pause after that edge). With the nominal phase 1 of 6 clocks, `rel_m` 1 and 2 strand every kind, 3 only DSWRITE and DSPTR (the edge E0+3 is the last high one), and 4 none. Another reset, a mode change or 400 clocks without the drop abort the plan.
- **Cross-check of the two forms.** At every release cycle, planned or not (a `pclk1` with the bench's own `rcyc` and `rst_fe` low), the bench evaluates design 9.5's edge form from its own `rst_fe` and the bus, never from `daria_fe`'s state:
  - the access committed at C is one that waits for a ready flag. The bench decodes it from the address, the direction, the data and upstream's DPC+ decode: a DFxDATA/DATAW/FRACDATA read, PUSH, WRITE, a taken CALLFUNCTION 1/2, DSWRITE or DSPTR;
  - `rst_fe` is low at C and at every later edge of the cycle;
  - `rst_fe` was high at an edge E0+j with j ≥ 4 (j ≥ 3 for DSWRITE and DSPTR) and j < C.

  The bench compares this with the observed form the class counts (`u_core.rcyc` at the `pclk1` with an action pending), and the decoded kind with the kind left pending. `ef_both` and `ef_none` count agreement. `ef_pred_only`, `ef_obs_only` and `ef_kind_bad` are must-be-0 (3). Mutants f1 and f2 (6) hold a ready flag, or the P32 capture, one clock longer than the design says. The observed form then strands actions the edge form does not, the class's resync hides the difference, and only this check fails.

## 3. The checks

### 3.1 The classes (design 9.5) as implemented

An audio class masks the replica (and, where noted, the counters and frequencies) from its own edge; at the next falling edge where both engines are quiet (both IDLE, nothing pending, no `tdef`, no `mwin`, no sample in flight, outside a merge window) upstream's state is deposited into `u_audio` (fe_taps.svh's rule) and the comparison resumes (`resync`).

| Class | Condition here | Effect |
|---|---|---|
| `short_phase1` | `u_seq.ev_short` (C < E0+6); checked against the bench's own phase count | L1 of that cycle (`short_dout`); `q26`: C3's pointer of such a cycle (B's word repaired from upstream's table at the falling edge after that `pclk1`; K and the full compare wait while such a repair may still come); `grant_steal` (`u_arb.ev_grant_steal`): replica, counters, frequencies |
| `merge_amp` | CDF, no hook: a refresh dispatched on either side in (M, M_fe+1] | replica |
| `ret_late` / `merge_race` | B's `call_tog` flip after upstream's completion | counter/frequency differences for 2,000 clocks are `merge_race`, and so are R1 seed/frequency differences of a call posted in that window (a call pending at X is captured after upstream's) |
| `dig_rom_lag` | upstream's ROM sample request with `digital_address` ≥ $8000 (B's port), or `sample_done` not high at R+4 (a DDR miss) | replica. So a resync after this mask alone, with no other class masking in the meantime, first compares the whole replica, the sum and AMPLITUDE included, and any difference is `dig_val_bad` (mutant u4, faults 7 and 8) |

| `tbl_alias` | `u_core.ev_tbl_alias` (a CDFJ+ DSWRITE byte into a pointer or increment word) | upstream's table copy of that word resynced from its own RAM at the next falling edge (as the ARM would rewrite it) |

| `rmw_svc` | `u_core.ev_rmw_svc` | information |
| `size_over32k` | `u_audio.ev_size_hi`, or upstream's SIZE read above 32 KB | replica |
| `pause_lane` | the stage-1 shadow's condition (`fe_shadow.svh`; F1_fixes.md 2, "The class as the benches count it"; design 9.5 states the same condition but still says this bench uses a wider one, 10.1): a sample capture on an unpaused edge (upstream in AUDIO_SAMPLE_CAPTURE, `u_audio` in SMCAP) right after an upstream grant clock with `pause` high; at the last clock with `pause` low (its edge is p) `sel_ram_sel` was 1; the two lane registers differ; `mapper_read_lane` equals the port's address lane recorded at p (`cartram_addr[1:0]`, the 6507's) and `al` the engine's lane recorded at p (`aud_addr[1:0]`, 0 under `cart_reset`). The kind comes from what is pending: `pend_c` = DSW, DSP or SVC (CALLFUNCTION 1/2), else `pend_r` (PUSH/WRITE, with `pend_s`), else `pend_s` (a DFx read; a field or PARAMETER write never strands, `bench_bad` if one did) | that cycle is not compared (3, first paragraph). A CALLFUNCTION 1/2: upstream's service leaves R2 (and R3's completion count), `service_pending` is not compared and K1, the full compare and the scheme events wait, until every service is done; then upstream's destination range is copied into B. `daria_fe` must make no copy: a `daria_fe` service latched in the next cycle is accepted only for an RMW's second write of 1 or 2 to $105A, paired by R2 with upstream's when upstream took it too, else dropped and resynced the same way (`rr_rmw_svc`); any other is `svc_bad`. Grants on such a range mask the replica (`rr_audio`). A differing 6507 read of a word in such a range, while it waits for its resync, is `rr_dout`; any other differing read falls through to the checks below it. The stall shape needs nothing: in mode A the 6507's hold is upstream's busy OR `daria_fe`'s. Every later difference is a failure. At every release cycle the edge form is checked against this observed form (2.5) |
| not reachable here | `pre_lock` (no BIOS path), `short_image` (images are ≥ 32 KB), `live_override` (no override without a load; the non-ARM interval is CDF-only, where nothing changes), `refresh_overlap` (lever not taken), mode-B classes | |

## 8. Observations

1. **Mode A cannot judge the stall release timing differentially.** Mutant s2 (`rel_ok` true at a `pclk1` edge) only moves when `daria_fe` releases its own hold; in mode A the 6507's hold is the OR of both sides' busies (bench.md limitation 1), so the bus is the same for both and no difference arises. The bench therefore checks design 2.1's rule on `daria_fe`'s own busy outputs (`rel_e0`, 3), which catches s2 (6). Whether the release is right against a 6507 held by DARIA alone is mode B's question (lane E1's stage 2).
2. **The ARM's cart RAM writes race the stream only in mode A** (item 6 of section 7): in hardware the ARM runs only while the 6507 is held. The bench keeps the race out rather than classifying it.
3. **`ret_late` comes only from very short calls** (the agent returns before upstream's first capture edge): 2,320 in the final campaign, against 632,996 returns on upstream's edge, and its `merge_race` window held 21 differences (5.2).
4. **`p32_reset`** (`a_p32_late` under a console reset, lane A O-1) occurs about 2.4 times per million cycles (255 in the final campaign), always in a 6507 cycle with `cart_reset` or `rst_fe` high; in the `+rst_bus=1` groups it marks the DSWRITE and DSPTR release cycles (948, 5.3).
5. **`q26` is not rare**: about one cycle in 1,500 with `+pg_mode=mix` (17,292 in the 25 M cycles of the final `mix` group; 151,963 in the whole campaign) makes upstream's Q26 pointer from a stale table read (a phase 1 of one or two clocks), and it can fall in the held fetch that starts a call (item 13).
6. **The arbiter's `cr_wb` and `cr_p32` are never requested together** (coverage counter `wb_and_p32_requested` 0 in every run), and three R requests at once are rare (`three_r_requests` 29 in the final campaign, in 4 of its 42 runs): `rdW` is cleared at every `pclk1` and set no earlier than k[3], P32 is requested only in k[1]/k[2], so a write-back never meets a P32 request; mutant a2 (that grant without `!cr_p32`) is equivalent by construction, in any mode, and is not in the mutant list (6); the yield order among three R requesters is exercised only those 29 times.
7. **`pause_lane` is reachable** (section 7 item 14), against lane B's B-1 ("`pause_lane` becomes unreachable"). B-1 reasons that a paused cycle's select is what it was at the last unpaused edge; but the lane register samples the port's address *before* that edge, and when that edge is the `pclk1` that ends a cycle with the RAM select high, the select is high there and low through the pause. Upstream's lane then freezes at the 6507's byte lane, `al` at the engine's (0). A grant in the pause whose capture lands on the first unpaused edge reads different bytes (one sample byte of AMPLITUDE). The design counts `pause_lane` (9.5), so this is a class, not an RTL issue. The lead decided not to make it exact (F1_fixes.md 2: no exact equivalent exists, the near-exact form costs about 12 ALMs, and the Pocket never pauses the core); the bench now counts only its exact form and fails every other lane difference (3.1).

## 9. Deviations from the task and limitations

- **Mode A only.** `clk_arm` is upstream's (5 × `clk_sys`, fixed phase), so the guard never locks and none of the guard's paths or mode B's classes are judged here, and DARIA's own stall release only by its edge rule (`rel_e0`; observation 1; lane E1's stage 2 is the place for the rest).
- **Models, not RTL, for three upstream blocks.** `arm_mapper_controller` (both halves copied without `arm7tdmi_pkg`), `arm_mapper_memory`'s DMA and sample ports (both clock halves exact, the DDR3 channel replaced by one random-latency server) and the subsystem's `mapper_reset_arm`. The self-check (4.1) shows the cluster, as wired, is deterministic against itself, not that the models equal the originals; their source lines are cited in `fe_rand_up.sv`.
- **The CPU behind the controllers is an agent.** It writes cart RAM only while the 6507 is held (observation 2) and returns random values; it never runs real ARM code.
- **The stream is program-like, not a 6502.** It obeys the rules of 2.3 (write sequencing, three reads before a store, the operand after an arming read, the opcode fetch after a store, stack-page reads in reset); every one of them was added because a failure showed the bench producing something a 6507 cannot (section 7). Patterns a real program makes and these rules forbid are not covered (for example a store right after a read that returned `$A9` as data). The one deliberate exception is `+rst_bus=1` (2.5): register reads and writes in the cycle a reset ends, which no 6502 makes, to reach design 9.5's `rst_release`.
- **Events are placed where the design is exact.** The non-ARM-scheme and 7800-mode switches wait for a `pclk1` with nothing in flight and no pointer check pending (items 19, 20); a live override in the middle of a call (`live_override`) is therefore not exercised.
- **Not reachable here:** `pre_lock`, `short_image`, `live_override`, `refresh_overlap` and the mode-B classes (3.1).
- **Coverage gaps** (observation 6): `cr_wb` with `cr_p32` never occurs, and three R requesters at once only 29 times in 105 M cycles. In the `rst_release` handling, the path that drops a `daria_fe`-only service after a dropped CALLFUNCTION (`rr_rmw_svc`) is not reached (5.3).

## 10. Open questions

1. RTL issue 1 (E3_rtl_issues.md): clear pending post actions at `pclk1`, gate the commit on a cycle that started out of `rst_fe`, or document it beside lane A's O-1? **Decided** (F1_fixes.md 1): option (a), the three post actions clear at `pclk1`, with `rcyc` for `a_pend_late`; the release cycle is design 9.5's `rst_release` (5.3).
2. `pause_lane` (note 1): accept the class (the design counts it) or make `al` follow the port's address so it becomes exact? **Decided** (F1_fixes.md 2): accepted, not made exact; the bench counts only the exact form (3.1).

## 11. Reproducing

In `sim/bupchip/daria/fe_rand/` (outputs under `sim/work/bupchip/daria/fe_rand/`; every log names its build stamp in its first and last lines):

```sh
./run_rand.sh 7 +cycles=400000                     # one daria_fe run (default plusargs)
SELF=1 ./run_rand.sh 7 +cycles=400000              # the upstream-vs-upstream self-check
POISON=1 ./run_rand.sh 7                           # daria_mem's poisoned RAM model
./run_rand.sh 7 +pg_mode=pause +only=dpc +hook=1   # a focused run
./run_rand.sh 7 +trace_from=N +trace_to=M          # per-clock trace lines T/TC/TA, TR at an rst_release (+dbg_word=W for one word)
./run_rand.sh 14 +cycles=20000 +inj=K +inj_at=5000 # self-test fault K (1-5): must FAIL
./run_rand.sh 7 +cycles=200000 +epoch=10000 +rst_bus=1 +resets=6 +only=dpc +inj=6 +inj_at=1000   # fault 6: must FAIL
./run_rand.sh 31 +cycles=150000 +epoch=25000 +pg_mode=mix +only=cdf +inj=K +inj_at=1000          # faults 7, 8: must FAIL
STAMP_ONLY=1 ./run_rand.sh                         # the build's stamp, without building (SELF=1, POISON=1, MUT_DIR as for a run)
./run_rand.sh 161 +cycles=1000000 +epoch=10000 +rst_bus=1 +resets=6 +only=dpc +pg_mode=mix      # rst_release (DPC+), as rst_dpc
./campaign.sh self; ./campaign.sh rst; ./campaign.sh fe; ./campaign.sh sum   # section 4, 5.3, 5.1-5.2, the totals and coverage
./mut_rand.sh                                      # the 31 mutants (CYCLES, SEEDS); ./mut_rand.sh r1 l3 for some
```

`./campaign.sh rst` makes the copy of F1's RTL without its `pclk1` clears itself (`$WORK/oldrtl/daria_fe_core.sv`: the tree's file with its three `| pclk1)` clears removed, lines 307, 509 and 536, and it checks that exactly those three lines differ); a single run against it is `MUT_DIR=$WORK/oldrtl ./run_rand.sh 161 <the rst_dpc plusargs>`. Every campaign group runs with `SKIP_DONE=1`: a restarted piece (`setsid nohup ./campaign.sh fe ... > log 2>&1 < /dev/null &`) skips each seed whose log already has a verdict on the current build stamp and plusargs.

Runs take about 125 µs of host time per 6507 cycle on this machine with two at a time (a 2.5 M-cycle seed in 5-6 minutes; the `+rst_bus=1` groups about 180 s per million cycles, since each of their resets adds an init).
